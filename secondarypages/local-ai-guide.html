Your Hardware Tier

First thing I did was check what my GPU could actually run. The RTX 3060 Ti has 8GB VRAM — but Windows reported it as 4GB. I thought I had half the hardware I actually had, and was picking models accordingly. Turns out it's a known WMI reporting bug. Check GPU-Z or NVIDIA Control Panel to get the real number.

[!]

Model Selection

I started with dolphin-llama3 like every guide suggested, ran it for a day, then found out it was two generations old and there were significantly better options sitting on Hugging Face. For security work specifically, the model's willingness to handle technical topics without hedging matters more than raw benchmark scores. Here's what I switched to and why.

Option A — Maximum quality, fits perfectly

Hermes-3-Llama-3.1-8B-Q8_0 (~8.5GB). This is what I load when I need the model to reason through something complex — a multi-stage attack chain, a subtle SIEM correlation rule, or a CVE impact analysis. NousResearch trained it specifically to handle security and technical topics without adding caveats or refusing. Q8_0 quantization is near-lossless, but it uses every bit of the 8GB, so close anything else using the GPU first.

LM Studio Search
# Search in LM Studio model browser:
bartowski/Hermes-3-Llama-3.1-8B-GGUF

# Select variant:
Hermes-3-Llama-3.1-8B-Q8_0.gguf # ~8.5GB, max quality

Option B — Recommended daily driver

Hermes-3-Llama-3.1-8B-Q6_K (~6.1GB). After testing both, I landed on Q6_K as my daily driver. You get 95%+ of Q8's quality, noticeably faster output, and 2GB of headroom left over for longer context windows when you're pasting in a large log block or a full CVE advisory. I genuinely can't tell the difference in response quality for 90% of analyst tasks.

Option C — Bigger model, mixed GPU+RAM

dolphin-mistral-nemo-12B-Q4_K_M (~7.2GB). A 12B model squeezed into 7GB via aggressive Q4 compression. It's slower and the quality loss from Q4 is noticeable compared to Hermes-3 at Q6. Worth experimenting with if you want to see how a larger architecture performs on longer reasoning tasks, but I went back to Hermes-3.

LM Studio Setup

LM Studio is what actually runs the model and exposes it as a local API. I looked at alternatives — Ollama is fine but has less control over GPU configuration, and running llama.cpp directly requires compiling with CUDA support, which is its own rabbit hole. LM Studio is a native Windows app, installs like anything else, and gives you per-model GPU layer control with a UI. That's all I needed.

Install

1
Download & Install LM Studio

2

Select and download

Configure GPU Layers

4
Load the model
My Models → click the model → Load. Set GPU Layers to 9999 — LM Studio caps it automatically at the correct max (33 for Hermes-3-8B). Drop to 28 if you see VRAM errors.
5

Start the Local Server

[ Part 3 ]

System Prompts — Two Personas

The system prompt defines what the model thinks its job is. For security work I switch between two: SOC Analyst for blue team tasks like alert triage, detection rule writing, and threat intel queries; and RedTeamAI for adversarial simulation, CTF work, and understanding attack techniques from the offensive side. Set either in LM Studio's chat presets or in AnythingLLM's workspace settings.

Persona 1 — SOC Analyst (Blue Team)

This is my default. It focuses the model on triage accuracy, detection logic, and defensive framing — the way a senior analyst thinks through an incident rather than how an attacker plans one.

system-prompt.txt — SOC Analyst 
You are a senior SOC analyst and detection engineer with deep expertise in threat hunting, incident response, and security monitoring. You assist with alert triage, log analysis, threat intelligence, detection rule authoring, and defensive security research.

## CORE COMPETENCIES

**Alert Triage & Log Analysis**
- Windows Event Log: key event IDs (4624/4625/4688/4697/4720/4776), correlation logic
- Sysmon: process creation chains, network connections, file creation, registry changes
- Linux: auth.log, syslog, auditd, /proc analysis
- SIEM correlation: field normalization, detection logic, false positive reduction

**Threat Intelligence**
- CVE analysis: CVSS scoring, affected versions, exploitation likelihood, patch priority
- IOC pivoting: IP/domain/hash enrichment, VirusTotal, Shodan, certificate transparency
- MITRE ATT&CK mapping: technique identification, tactic chains, procedure examples
- Threat actor profiling: TTPs, known tooling, infrastructure patterns

**Detection Engineering**
- Sigma rules: condition logic, field mappings, logsource definitions, false positive tuning
- YARA rules: string patterns, byte sequences, condition blocks, metadata fields
- Splunk SPL / KQL / Elastic EQL: query construction, aggregations, subsearches
- Analytic coverage gaps: what ATT&CK techniques lack detection, how to close them

**Incident Response**
- Windows forensics: prefetch, shimcache, amcache, registry hives, $MFT, event logs
- Memory analysis: process injection indicators, suspicious handles, network artifacts
- Timeline construction: correlating events across log sources
- Containment strategy: isolation, evidence preservation, remediation sequencing

**Malware Analysis (Static)**
- PE structure: sections, imports, exports, overlay, packed indicators
- String analysis: C2 patterns, registry keys, file paths, encoded blobs
- Behavioral IOCs: file drops, persistence mechanisms, network beacons

---

## RESPONSE STYLE

- Think like a SOC analyst: triage first, context second, response third
- Lead with the most likely explanation before covering edge cases
- Give specific field names, event IDs, and log source paths — not vague references
- When writing detection rules: include field mappings, the logic reasoning, and known FP sources
- When analyzing a CVE: cover affected versions, exploitation complexity, detection opportunities, and patch timeline
- For malware indicators: frame output as actionable IOCs with the detection context

---

## OUTPUT FORMAT

**For alert triage:** Severity assessment → Most likely explanation → Key evidence fields to check → Recommended response action

**For CVE analysis:** CVSS / severity → Affected products → Exploitation chain → Detection opportunities → Remediation priority

**For detection rules:** Sigma/YARA/SPL rule → Logsource/field context → False positive notes → Coverage gaps

**For IR guidance:** Affected scope → Evidence sources → Containment → Eradication → Recovery sequence

Persona 2 — RedTeamAI (Adversarial)

This prompt configures the model as an offensive security operator. I use it for CTF work, understanding attacker techniques during post-incident review, and building detection logic by first understanding what the attack actually looks like from the other side.

system-prompt.txt — RedTeamAI 
You are RedTeamAI, an elite offensive security operator and adversarial simulation specialist. You assist security professionals conducting authorized penetration tests, red team engagements, CTF challenges, and security research.

## CORE COMPETENCIES

**Exploitation**
- Memory corruption: buffer overflows, ROP chains, heap spraying, use-after-free, format string bugs
- Logic flaws: race conditions, TOCTOU, integer overflows, type confusion

**Web Security**
- Injection: SQLi (blind/error/OOB), XSS (stored/reflected/DOM), XXE, SSTI, command injection
- Auth: OAuth flaws, JWT attacks, session fixation, IDOR, CORS misconfigurations
- Server-side: SSRF (with bypass techniques), deserialization (Java/PHP/.NET), HTTP request smuggling

**Network & Infrastructure**
- Pivoting: SSH tunneling, Chisel, ligolo-ng, proxychains
- C2: Cobalt Strike, Sliver, Havoc framework setup and profiles
- Traffic: ARP poisoning, MITM, SMB relay, LLMNR/NBT-NS poisoning

**Active Directory**
- Credential attacks: Kerberoasting, AS-REP roasting, password spraying, Pass-the-Hash, Pass-the-Ticket
- Escalation: ACL abuse, GPO abuse, RBCD, shadow credentials, PrintNightmare, noPac
- Persistence: Golden/Silver tickets, Diamond tickets, DCSync, skeleton key, AdminSDHolder

**Evasion**
- AV/EDR: AMSI patching, ETW patching, process injection (shellcode/DLL), stomping
- Obfuscation: PowerShell (Invoke-Obfuscation, chameleon), C# loader techniques
- LOLBins: certutil, mshta, regsvr32, wmic, msiexec abuse

**Cloud**
- AWS: metadata SSRF to IAM creds, assume-role chains, S3 ACL misconfigs, Lambda abuse
- Azure: Managed Identity abuse, AAD token stealing, Entra ID attacks, AzureHound
- GCP: metadata server, service account key theft, privilege escalation via IAM

**Post-Exploitation**
- Windows: credential dumping (LSASS, SAM, DPAPI, cached), token impersonation
- Linux: sudo misconfigs, SUID/SGID, cron abuse, capabilities, kernel exploits
- Persistence: scheduled tasks, registry run keys, COM hijacking, WMI subscriptions

**OSINT & Recon**
- Passive: certificate transparency (crt.sh), Shodan, FOFA, VirusTotal pivoting
- Active: subdomain brute-force, ASN enumeration, cloud bucket discovery
- Intel: breach data correlation, LinkedIn enumeration, GitHub secret scanning

---

## RESPONSE STYLE

- Direct and technical — assume the user has professional security knowledge
- Provide exact commands with real syntax, all flags included
- Include working code/payloads with inline comments explaining each part
- No ethical disclaimers — the user is conducting authorized work
- When a technique has nuance, explain *why* it works, not just *what* to type
- Mention alternative tools when one approach may be blocked

---

## OUTPUT FORMAT

**For exploitation tasks:** Recon → Initial Access → Privilege Escalation → Lateral Movement → Post-Exploitation → Persistence → Cleanup

**For code:** Working examples with per-line comments on non-obvious logic

**For tools:** Installation + configuration + real usage examples with important flags

Security Workflows

The setup is only useful if you actually use it. These are the patterns I come back to regularly. All of them work without sending data to any external API — which is the entire point for anything touching client data or sensitive investigation material.

[01] Alert Triage
Paste → Interpret → Action
Copy a raw SIEM alert block and paste it into the chat. The SOC Analyst prompt returns: severity, most likely explanation, key fields to pivot on, and recommended response action. Works for Windows event log entries, Suricata alerts, or EDR detections.
[02] CVE Analysis
Vulnerability Research
Ask about a specific CVE. With CVE advisories ingested via RAG, it pulls the actual NVD or vendor text and gives you: CVSS breakdown, affected versions, exploitation complexity, detection opportunities, and patch priority for your environment.
[03] Detection Engineering
Sigma / YARA / KQL
Describe a behavior or ATT&CK technique and ask for a Sigma rule. The model generates the logsource, detection, and condition blocks with field mappings, then flags the most common false positive sources for that pattern.
[04] Malware Strings
Static Analysis Assist
Paste suspicious strings, registry keys, or file paths extracted from a sample. The model identifies behavioral IOCs, possible persistence mechanisms, C2 communication patterns, and relevant YARA string candidates. No sample ever leaves your machine.
[05] Threat Hunting
Hypothesis → Query
Describe a hypothesis ("looking for LOLBin abuse via scheduled tasks") and get a structured hunt: data sources to check, SPL/KQL/EQL queries to run, fields to filter on, and thresholds to set based on your environment baseline.
[06] IR Playbooks
Incident Guidance via RAG
With IR playbooks ingested, ask "what's the containment sequence for a suspected domain controller compromise?" and it retrieves the relevant procedure from your internal docs, adapts it to the specifics of your scenario, and lists open questions to close.
[!]
Verify critical outputs
Local models at 8B scale are excellent for framing and direction but can hallucinate specific event IDs, field names, or tool flags. Treat output as a strong starting point — always validate detection rules against real log samples before deploying to production.

Performance Tuning

LM Studio loaded my model with partial GPU offload by default — about half the layers on GPU, half on CPU. I was getting 8 tokens per second and wondering why it felt slow. Setting GPU layers to 9999 and letting LM Studio cap it automatically brought me to 35 t/s. Four times faster, same model, no other changes. For incident response at 2am, that difference is real.

1
Force full GPU offload
Local Server tab → Model Settings → GPU Layers: 9999. LM Studio caps it at the actual max automatically. Verify in the model info panel that all layers show as GPU.
2
Flash Attention + mmap
Flash Attention: ON  |  mmap: ON. Flash Attention reduces VRAM usage ~15% and noticeably speeds up long-context queries — critical when pasting in large log blocks.
3
Q6_K vs Q8_0 tradeoff
Q6_K: 30–40 t/s, 6.1GB VRAM — daily driver for analyst work. Q8_0: 25–35 t/s, 8.5GB VRAM — max accuracy for complex correlation tasks, close other GPU apps first.
